# V4.2.8 — Fast Progressive Tracking

Scope: tracking responsiveness only. Duty Calculator, HS search, Sea Services, and unrelated features are unchanged.

## Changes
- Tracking remains serial at the WKWebView layer to preserve the real-device stability fix.
- The UI now receives a progressive result after the first source completes, then updates the same result after the second source completes.
- Optimized airline adapters (Oman Air 910, Emirates 176, Turkish 235) are tried first.
- Generic/adaptive airline pages use Transom first so a difficult airline site cannot delay the first useful result.
- Adaptive airline automation now has an approximately 15–16 second ceiling instead of the old 45–52 second worst-case wait.
- Saved Cargo Board data is displayed immediately when re-tracking an already saved AWB, then refreshed live.
- Cargo Board refresh applies each progressive source update as it arrives and preserves the last verified live source if the other source temporarily fails.
- The tracking screen displays a small “Updating the second source…” indicator after the first result is visible.

## Reliability guardrails
- No parallel hidden WKWebViews were introduced.
- No shipment events are fabricated.
- Existing live snapshots are preserved during partial/failed refreshes.
